4 Retrieval & just-in-time context loading

Keep the corpus outside the model and pull in only the slice a step needs: document chunks, code symbols, tool definitions, memories, MCP resources. RAG is the oldest context trick and still the main cost and attention control even with million-token windows; coding agents, MCP hosts and Claude's tool search all ship a form of it.

Problem it solvesRecall degrades as tokens pile up (context rot) and cost scales with every token, yet the facts, code or tools a step needs are a tiny fraction of what is available.

How it works

One idea, several forms: heavy data stays outside the window, a cheap pointer stays inside. Classic RAG indexes chunks and injects the top-k hits; advanced and modular RAG add query rewriting, hybrid BM25 plus vector search, metadata filters, re-ranking and routing across specialized indices. Agentic RAG hands the loop to the model: plan, retrieve, reflect on sufficiency, retrieve again or switch source (corrective and adaptive loops, single or multi-agent). Just-in-time retrieval drops the index for lightweight identifiers the agent follows itself (file paths, URIs, glob, grep, head, tail), disclosing detail progressively. The same pattern covers tool definitions (search plus deferred loading), memories (vector or graph lookup) and MCP resources, where the host, not the model, decides which URIs enter context. Self-Route adds a switch: answer from retrieved chunks when they suffice, otherwise fall back to the full long context.

How to achieve it

  1. Pick the unit of retrieval and index it. Chunk documents with metadata; for code, parse the repo with tree-sitter and rank symbols by incoming references (aider's repo map fits the top signatures into about 1k tokens via --map-tokens); for tools, index names, descriptions and argument descriptions.
  2. Build retrieval evals before tuning. Generate synthetic question-to-chunk pairs, score retriever precision and recall apart from answer quality, then cluster real queries (even 100 reveal patterns) to split content gaps from capability gaps.
  3. Retrieve hybrid and re-rank. Combine full-text or grep with embeddings, filter on extracted metadata, re-rank candidates, and route queries to specialized indices instead of one flat store.
  4. Give the agent handles, not payloads. Expose read, grep and glob tools, file paths and MCP resource URIs; preload a small high-value set (a rules file, the 3 to 5 hottest tools) and defer the rest to on-demand search.
  5. Close the loop agentically. After each retrieval the model judges sufficiency, reformulates or switches source, and stops at a hard iteration cap.
  6. Route between retrieval and raw long context. Try RAG first; if the model declares the chunks insufficient, resend with the full document. Track per-query cost and retrieval hit rate.
import anthropic

client = anthropic.Anthropic()

def deferred(name, description, schema):
    return {"name": name, "description": description,
            "input_schema": schema, "defer_loading": True}

tools = [
    # the search tool itself must stay loaded
    {"type": "tool_search_tool_bm25_20251119", "name": "tool_search_tool_bm25"},
    # hot-path tool: always in context
    {"name": "read_file", "description": "Read a file by path",
     "input_schema": {"type": "object",
                      "properties": {"path": {"type": "string"}},
                      "required": ["path"]}},
    # hundreds more like this: loaded only when a search matches
    deferred("github_list_prs", "List open pull requests in a repo",
             {"type": "object", "properties": {"repo": {"type": "string"}},
              "required": ["repo"]}),
]

resp = client.messages.create(
    model="claude-sonnet-4-6", max_tokens=1024, tools=tools,
    messages=[{"role": "user", "content": "Which PRs are open on acme/api?"}],
)
# resp.content: server_tool_use -> tool_search_tool_result -> tool_use

Variants & tools

  • aider repo map — tree-sitter definitions and references, graph-ranked into a ~1k-token map of signatures; widely copied by later coding agents.
  • Anthropic tool search tool — defer_loading: true plus a regex or BM25 search tool; cuts a ~55k-token multi-server tool prefix by over 85%, caching intact.
  • Claude Code MCP tool search — deferred discovery for MCP servers in Claude Code and the Agent SDK.
  • MCP Resources — URI-addressed data with list, read, templates and subscribe; the host, not the model, chooses what loads.
  • LlamaIndex — indices, query engines, routers, agentic retrieval; 51.8k stars.
  • LangChain / LangGraph "select" — retrieval over memories, tools and knowledge; cites Windsurf's grep + AST + knowledge-graph + re-rank stack.
  • Sourcegraph code search pipelines — production context pipelines for coding agents: search, retrieve, prune, order high-signal material first or last.
  • Self-Route — per-query routing between RAG and long context; 65% (Gemini-1.5-Pro) and 39% (GPT-4o) cost reduction at near long-context quality.

Trade-offs & pitfalls

  • Retrieval quality is the ceiling. When affordable, long context beats RAG on average (Li et al.); retrieval wins on cost, so measure the gap and route rather than pick a side.
  • Embedding search degrades as the corpus grows. Windsurf calls it unreliable at scale and layers grep, AST parsing, knowledge graphs and re-ranking on top.
  • Runtime exploration is slower than precomputed retrieval, and an unguided agent wastes context misusing tools or chasing dead ends (Anthropic). Cap iterations; preload the predictable part.
  • Tool overload is real: DeepSeek-v3 confuses tools above 30 and nearly always fails past 100; Llama 3.1 8b fails with 46 tools but succeeds with 19 (Breunig). Keep 3 to 5 hot tools loaded, never defer the search tool itself.
  • Evaluate the retriever, not just the answer. Without synthetic precision/recall sets and query clustering you tune blind; position effects (lost in the middle) can hide good hits.
