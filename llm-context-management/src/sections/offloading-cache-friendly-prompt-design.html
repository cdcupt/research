5 Context offloading and cache-friendly prompt structure

Treat the context window as a deliberately laid-out, append-only buffer and everything else as external state. Raw tool output, plans and notes go to files with pointers left behind; the prompt prefix never changes, so the provider's KV cache keeps hitting. Manus, Claude Code, Cline and LangChain's Deep Agents converge on this shape.

Problem it solvesAgent transcripts bloat with tool output and are re-sent every turn at full price, so the window must be both small and byte-stable.

How it works

Every turn re-sends the whole transcript, and Manus reports an input-to-output ratio near 100:1, so input tokens dominate cost and latency. Providers serve a repeated prompt prefix from KV cache at about a tenth of the price: Anthropic bills cache reads at 0.1x and writes at 1.25x, OpenAI applies an automatic cached-input discount (no write premium; the rate varies by model), and Gemini 2.5+ caches implicitly. Keep the prefix identical: static system prompt first, no timestamps, deterministic serialization, append-only events, a fixed tool list. Then shrink the window without editing that prefix: write tool output to the sandbox filesystem and leave a restorable path or URL, keep the plan in a todo.md the agent rewrites at the tail of the context so goals stay in recent attention, and let grep or sub-agents re-read files on demand.

How to achieve it

  1. Lay the prompt out in stability order: tools, system prompt, canonical examples, then messages. Strip timestamps and request IDs, and pin serialization (key order, whitespace) so identical state produces identical bytes.
  2. Put a cache breakpoint on the last constant block (Anthropic cache_control, OpenAI prompt_cache_key, Gemini explicit CachedContent) and log cache_read_input_tokens or cached_tokens on every request. Treat hit rate as an SLO.
  3. Offload tool output: write the raw result to a file and keep a short pointer (path, size, first lines) in the event log; restore with read_file or grep only when needed. Compact stale results to pointers first; summarize only when that runs out.
  4. Recite goals in a todo.md or NOTES.md the agent rewrites after each step. Anthropic's note-taking agent kept exact tallies across thousands of steps and resumed after context resets from its notes.
  5. Curate the action space instead of swapping it: keep tool definitions fixed, use consistent name prefixes such as browser_ and shell_, and constrain choice with logit masking or response prefill rather than adding or removing tools mid-task.
  6. Own the serialization: write your own thread_to_prompt() over an event log (12-Factor, Factor 3) so you decide density and how errors appear. Keep failed calls in, add small variation to avoid few-shot ruts, and budget utilization (Cline: 70-80% fill; Horthy: about 40%).
import anthropic, hashlib, pathlib

client = anthropic.Anthropic()
SCRATCH = pathlib.Path("scratch"); SCRATCH.mkdir(exist_ok=True)
events = []  # append-only; never rewrite earlier entries

def offload(tool_name: str, raw: str) -> str:
    """Write raw tool output to disk; keep a restorable pointer in context."""
    path = SCRATCH / f"{tool_name}-{hashlib.sha1(raw.encode()).hexdigest()[:10]}.txt"
    path.write_text(raw)
    return (f"<{tool_name}_result path=\"{path}\" bytes={len(raw)}>\n"
            f"{raw[:400]}\n...(truncated; read_file to restore)\n</{tool_name}_result>")

def step(user_text: str):
    events.append({"role": "user", "content": user_text})
    resp = client.messages.create(
        model="claude-opus-5",
        max_tokens=1024,
        tools=TOOLS,  # fixed list, never pruned mid-task
        system=[{"type": "text", "text": SYSTEM_PROMPT,  # static: no clock, no IDs
                 "cache_control": {"type": "ephemeral"}}],  # breakpoint on stable prefix
        messages=events,
    )
    events.append({"role": "assistant", "content": resp.content})
    u = resp.usage
    total = u.cache_read_input_tokens + u.cache_creation_input_tokens + u.input_tokens
    print(f"kv-cache hit rate: {u.cache_read_input_tokens / max(total, 1):.0%}")
    return resp

Variants & tools

  • Manus — stable prefix, logit-masked tools, filesystem as context, todo.md recitation.
  • LangChain Deep Agents — write_todos middleware, virtual filesystem, sub-agents; LangChain's default harness.
  • 12-Factor Agents, Factor 3 — custom token-dense event-log serialization instead of the framework message list.
  • Anthropic context editing — server-side clear_tool_uses swaps old tool results for placeholders past a token trigger.
  • Anthropic, OpenAI and Gemini prompt caching — explicit breakpoints, automatic prefix caching with routing keys, and implicit plus explicit caches.
  • Cline — context progress bar and a new_task handoff that preloads only rule-selected state.
  • TokenPilot — research framework that compacts and evicts context while keeping prefix cache hits.
  • Harrison Chase, "Filesystems for context engineering!" — a filesystem as the pragmatic primitive for agent state.

Trade-offs & pitfalls

  • The cache is fragile: one changed token, a reordered tool, an added image or a new tool_choice invalidates everything after it. Minimum cacheable sizes vary (512-4,096 tokens on Claude, 1,024 on OpenAI, 2,048-4,096 on Gemini) and default TTLs are minutes; verify hits from usage fields.
  • Compaction and caching pull in opposite directions: rewriting old messages breaks the prefix hash. Compact rarely, at breakpoints, and prefer pointer substitution to summaries; TokenPilot reports 56 to 87 percent cost reductions from co-designing the two.
  • Pointers only help if restoration is cheap and the model knows to use it; you trade tokens for extra tool calls. A summary that drops the one relevant detail is irreversible, so keep the raw file.
  • Logit masking assumes you control decoding or the provider exposes prefill. On the Claude API, toggling tool_choice per turn still invalidates the cached messages prefix, so steer through the prompt where possible.
  • Recitation costs tokens every turn: Manus found about a third of its actions went to task-list updates before moving planning into a dedicated planner agent.
