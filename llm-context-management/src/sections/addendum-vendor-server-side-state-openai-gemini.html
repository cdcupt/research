9 Vendor-managed conversation state and server-side compaction (OpenAI, Gemini)

Instead of re-sending the whole transcript every turn, you hand the provider an id and it replays, stores and, on request, compacts the thread. OpenAI does this with previous_response_id, the Conversations API and /responses/compact; Gemini does it with the Interactions API and previous_interaction_id. Teams use it to cut payloads, raise cache hits and skip writing a summarizer.

Problem it solvesShipping the full transcript on every turn grows linearly and eventually overflows the window; vendor-held state removes the shipping and gives a one-parameter compaction instead of a hand-built summarizer.
Lifecycle stagewrite — provider persists, then compacts, the thread
Popularity signals12 sources in this survey; first-class API surface at OpenAI (Responses, Conversations, compaction, mirrored on Azure) and Google (Interactions API, GA June 2026); wrapped by OpenAI Agents SDK sessions, LangChain and Agno; open feature requests in Vercel AI SDK, pydantic-ai and opencode.

How it works

OpenAI's Responses API offers three modes. Manual: you send the full input array, including encrypted reasoning items. Chained: you send only the new message plus previous_response_id; the server replays the stored chain, but every prior input token is still billed each turn, and stored responses expire after 30 days unless store=false. Persistent: a Conversation object with its own id holds items (messages, tool calls, tool outputs) with no 30-day TTL and is prepended to each request. On top of either, context_management=[{"type":"compaction","compact_threshold":N}] makes the server swap old items for an opaque, encrypted compaction item once the rendered context crosses N tokens; /responses/compact does the same on demand for a history you hold yourself. Gemini's Interactions API mirrors the chained mode: previous_interaction_id, store=true by default, 55-day (paid) or 1-day (free) retention, and better implicit-cache hits than resending history.

How to achieve it

  1. Pick a mode. Use manual arrays when you need full control, previous_response_id for simple chains, and conversation= when the thread must survive sessions or devices. On Gemini, call interactions.create with previous_interaction_id (google-genai 2.3.0 or later).
  2. Decide storage. Keep store=true if you want to continue by id. Set store=false for zero data retention, and then carry every output item yourself, including encrypted reasoning and compaction items.
  3. Turn on server compaction. Add a context_management compaction entry with a compact_threshold below the model window (OpenAI's examples use 200,000). Keep the compaction item in the window and never prune by hand when chaining by id.
  4. For a self-held history, call responses.compact when your own trigger fires (the Agents SDK default is ten non-user items) and treat the returned output as the canonical next window.
  5. Budget tokens explicitly. On Gemini call count_tokens before sending and read usage.total_cached_tokens after; on OpenAI set truncation="auto" as a last-resort guard so an overflow drops the middle instead of returning HTTP 400.
  6. Re-send interaction-scoped settings each turn (Gemini: tools, system_instruction, generation_config) and keep your own durable record of thread ids, because retention windows expire.
from openai import OpenAI
from google import genai

oa = OpenAI()
# 1) OpenAI: server holds the thread and compacts it past 200k rendered tokens
first = oa.responses.create(model="gpt-5.6", input="Audit this repo for flaky tests.")
nxt = oa.responses.create(
    model="gpt-5.6",
    previous_response_id=first.id,   # server replays prior turns
    input=[{"role": "user", "content": "Now fix the top three."}],
    context_management=[{"type": "compaction", "compact_threshold": 200_000}],
    store=True,                      # default; False for ZDR, then carry items yourself
)

# 2) Manual checkpoint for a history you keep client-side
compacted = oa.responses.compact(model="gpt-5.6", input=history_items)
history_items = compacted.output     # canonical next window, do not prune it

# 3) Gemini: same idea with the Interactions API
g = genai.Client()
i1 = g.interactions.create(model="gemini-3.7-flash", input="Hi, my name is Bob")
i2 = g.interactions.create(
    model="gemini-3.7-flash",
    input="What's my name?",
    previous_interaction_id=i1.id,   # stored 55 days (paid) or 1 day (free)
)
print(i2.usage.total_input_tokens, i2.usage.total_cached_tokens)

Variants & tools

  • OpenAI Conversations API — durable conversation object whose items (messages, tool calls, outputs) are prepended to each Responses call; no 30-day TTL.
  • OpenAI /responses/compact — stateless, ZDR-friendly endpoint that returns a shorter window containing an encrypted compaction item.
  • OpenAI Agents SDK Sessions — OpenAIConversationsSession delegates history to the Conversations API; OpenAIResponsesCompactionSession wraps any session and calls responses.compact on a trigger.
  • LangChain ChatOpenAI use_previous_response_id — drops messages up to the last response from the payload and sends the id instead.
  • Azure OpenAI Responses API — same surface on Azure, including context_management compaction and responses.delete.
  • Gemini Interactions API — previous_interaction_id, store, tiered retention, background execution; replaces generateContent for new projects.
  • google-genai / Firebase chat sessions — the older client-side model: the SDK keeps history locally and your app trims it.
  • Agno Gemini Interactions provider — framework integration that rides the server-side state.

Trade-offs & pitfalls

  • Billing does not shrink. A previous_response_id chain still bills all prior input tokens every turn; only compaction reduces the rendered context, and caching lowers the price, not the count.
  • There is no token-cap knob for chains. Developers asked for an Assistants-style last_messages limit in July 2025 and got no staff answer; without truncation="auto" or compaction, overflow is a 400 error.
  • State is opaque. Compaction items are encrypted and "not intended to be human-interpretable"; you cannot inspect or edit what the model kept, and the thread is not portable across vendors.
  • Retention differs per vendor: OpenAI responses expire at 30 days, Gemini interactions at 55 days (paid) or 1 day (free); Gemini store=false disables id continuation and background execution, and Interactions still lacks explicit caching and Batch.
  • Mixing modes breaks things. Do not pair OpenAIResponsesCompactionSession with OpenAIConversationsSession; do not prune manually when chaining by id; with stateless arrays drop only items that precede the latest compaction item.
