★ Deep dive: why context windows stop near 1M — and how to push past it

Frontier windows cluster near 1M because three costs meet there: attention compute grows with the square of length, the KV cache grows linearly per token until it fills GPU memory, and measured quality decays long before the advertised limit. GPT's "~275K" was GPT-5's 400K window minus a 128K output reservation; GPT-5.6 Sol now lists 1.05M. Distributed serving removes the memory wall, not the quality wall.

The short answer1M is an economic and quality ceiling, not a physical one: Meta prefills 1M tokens of Llama 3 405B in 77 s on 128 H100s, but per-request cost and accuracy loss past tens of thousands of tokens make larger windows hard to sell. Distributed systems scale memory and compute; quality needs retrieval, compaction and sub-agents.

What the frontier actually offers today

As of 2026-08-21 every major vendor's API tier sits at 1M or just above, except xAI's newest Grok 4.6 and 4.5 (500K) and DeepSeek's open V3.x line (128K). The telling column is the last one: where an independent benchmark exists, the length at which a model still performs near its short-context baseline is one to three orders of magnitude below the nominal window. NoLiMa, which removes lexical overlap between question and evidence, puts GPT-4.1 (1M) at 16K and Llama 4 Scout (10M) at 1K. No suite has published GPT-5, Claude 4.x or Gemini 3 results, so those cells stay blank.

Why the window is capped: the four bottlenecks

Compute. Self-attention time and memory are quadratic in sequence length; FlashAttention makes exact attention IO-aware without changing that asymptote. Prefill is compute-bound, so time-to-first-token grows superlinearly with prompt size: Meta's 1M-token prefill of Llama 3 405B takes 77 s on 128 H100s at 63% FLOPS utilization, versus 3.8 s for 128K. Google said in February 2024 that 10M tokens was "close to the thermal limit of our Tensor Processing Units".

Memory. Every token leaves keys and values behind in every layer. NVIDIA's formula: KV bytes per token = 2 × layers × kv_heads × head_dim × bytes. Llama 3 70B (80 layers, 8 grouped-query KV heads, dim 128, bf16) needs 0.33 MB per token, about 328 GB for one 1M-token request, more than four H100s of HBM before weights. AI21's Jamba table at 256K shows 128 GB of KV for LLaMA-2 7B against 4 GB for Jamba. Memory also sets decode speed: generation is bandwidth-bound and, as NVIDIA's Helix analysis notes, every output token streams the entire KV history, so latency rises and concurrent users per GPU fall with context.

Quality. Models lose accuracy well before the window is full. RULER measured GPT-4's effective length at 64K against a 128K claim. NoLiMa collapses effective lengths to single-digit thousands (GPT-4o 8K, Gemini 1.5 Pro 2K); at 32K eleven of thirteen models fall below half their short-context score. Chroma's "context rot" study of 18 models (Claude 4, GPT-4.1, o3, Gemini 2.5) found monotonic degradation even on trivial tasks. An EMNLP 2025 paper isolates length itself: accuracy drops 13.9% to 85% even when irrelevant tokens are replaced with whitespace. Anthropic's documentation now states that "as token count grows, accuracy and recall degrade".

Data and training. An et al. show effective context rarely exceeds half the training length because distant relative positions are under-represented in training. LongRoPE names why windows stalled near 128K: fine-tuning cost, scarcity of long documents, and catastrophic attention values at unseen positions. Llama 3 405B went from 8K to 128K through six stages on roughly 800B tokens. Qwen2.5-1M trains to 256K and reaches 1M only by Dual Chunk Attention extrapolation; Llama 4 Scout trained at 256K and markets 10M, which NoLiMa measures at 1K. Nominal windows mark where extrapolation stops erroring, not where the model was trained.

Why GPT defaults lower than 1M

Facts first. OpenAI's GPT-5 page, fetched 2026-08-21, lists a 400,000-token window, 128,000 max output tokens and $1.25 / $10 per million input / output; it states no input cap. Subtracting the output reservation gives the 272K in the question, but that split is arithmetic, not documented. The current flagship page, GPT-5.6 Sol, lists a 1,050,000-token window, 922,000 max input, 128,000 max output and $4 / $20: the 1M class is on offer at 3.2x GPT-5's input price. ChatGPT's per-plan windows could not be verified (pricing and help pages returned HTTP 403); a sibling sweep recorded that ChatGPT stayed at 32K when GPT-4.1 launched with 1M in the API.

Inference, labelled as such. OpenAI has published no rationale for 400K; three explanations fit its documentation. First, it prices input flat rather than tiering above 200K as Google and xAI do, so it caps the window instead of surcharging it and sells 1M as a dearer SKU. Second, reasoning models reserve 128K of the window for output and hidden reasoning. Third, OpenAI treats the window as a rolling cache: the Responses API holds state server-side via previous_response_id and, since February 2026, compacts automatically when rendered tokens cross context_management.compact_threshold, telling developers "do not manually prune". A model whose history is compacted on the server gains less from 1M.

How labs extend context

Architecture: shrink the cache or the attention. Grouped-query attention (Llama 3: 8 KV heads) divides KV memory by 8 to 16. Multi-head Latent Attention (DeepSeek-V2) caches one 576-value latent per layer instead of full keys and values, cutting cache 93.3% versus DeepSeek 67B; DeepSeek-V3 needs about 70 KB per token against roughly 4 MB for the same 128-head model without MLA. Gemma 3 keeps five local sliding-window layers per global layer. Sparse attention is now trained in: DeepSeek's NSA reads 5,632 instead of 65,536 tokens per decode step at 64K, DSA in V3.2 selects 2,048 KV tokens per query and shipped with a price cut above 50%, and Moonshot's MoBA serves Kimi at constant sparsity up to 10M. Linear and state-space hybrids replace most attention with constant-memory recurrence: Jamba (8x smaller KV), MiniMax-01 (trained at 1M, extrapolating to 4M, sized for one 8-GPU, 640 GB machine), Kimi Linear, Qwen3-Next (three Gated DeltaNet layers per attention layer). Test-time memory (Titans, Infini-attention) remains research.

Position and training. Positional Interpolation rescales RoPE indices into the trained range; YaRN extends Llama 2 to 128K with 10x fewer tokens; LongRoPE reaches 2,048K with at most 1K fine-tuning steps; Dual Chunk Attention remaps positions with no training. Under these sits a staged curriculum with rising RoPE base (Llama 3: 500,000; Qwen2.5-1M: 10 million) and data engineering: Fu et al. showed 1B to 5B balanced long tokens close the gap to GPT-4 at 128K, and Qwen generated synthetic long instructions with agents.

Serving. FlashAttention avoids materialising the n × n matrix; PagedAttention stores KV in virtual-memory-style blocks, raising throughput 2 to 4x; prefix caching (SGLang's radix tree, vendor prompt caching at 0.1x input price) reuses cache across requests; KV quantization (KIVI) and eviction (H2O, SnapKV, StreamingLLM) shrink it; chunked prefill stops one 1M request stalling everyone else.

If context is the bottleneck: distribute the window, or distribute the problem

Distributing the window. Ring Attention shards the sequence across devices and passes KV blocks around a ring, so supported length scales linearly with device count at exact attention. Meta's inference version (pass-KV and pass-Q context parallelism) is the production proof: 1M-token prefill of Llama 3 405B in 77 s on 128 H100s at 93% parallel efficiency. Disaggregated serving splits prefill and decode onto separate pools: Moonshot's Mooncake moves KV through an 800 Gbps RDMA pool built from the CPU DRAM and SSDs of its GPU servers, reaching about a 50% cache hit ratio and letting Kimi handle 75% more requests; NVIDIA Dynamo routes requests to the GPU already holding their prefix, offloads cold KV to host memory or object storage, and reports up to 30x throughput for DeepSeek-R1 on GB200 NVL72.

What this can and cannot fix. It removes the capacity wall: a 328 GB cache can span nodes or a DRAM/SSD pool, and a 1M prefill finishes in seconds. It does not reduce total work: attention FLOPs stay quadratic and are merely spread over more chips, every decode step still streams the full KV history, and the same customer pays, which is why Google and xAI double input price above 200K and OpenAI charges 3.2x for its 1M model. No hardware changes the weights, so the quality curves above are untouched.

Distributing the problem. The other route keeps each call short. Google's Chain of Agents passes a long input through 8K-window workers and a synthesiser, beating RAG and a 200K full-context baseline by up to 10% across eight datasets and by about 100% beyond 400K. Anthropic's recommendation even with 1M is proactive compaction, sub-agents that return only their result, and a memory tool; memory plus context editing gained 39% on agentic search. Both vendors now compact on the server; Anthropic's default trigger is 150K input tokens. Retrieval remains the cheapest lever: Databricks found most 2024 models peaked between 16K and 64K of retrieved context, and Google's own guide concedes an "inherent tradeoff between getting the right information retrieved and cost".

What this means for builders

  • Budget to the effective length, not the nominal one: plan for 32K to 64K of reliable working context and treat anything above 200K as paid storage, not reasoning.
  • Check the price cliff: Gemini 2.5 Pro and Grok 4.x double input cost at 200K, Claude 4.6+ does not, OpenAI's 1M model costs 3.2x its 400K sibling.
  • Put stable content first and cache it: cached input bills at about 0.1x but still occupies the window.
  • Default to server-side compaction and sub-agents for long agentic runs; both OpenAI and Anthropic now advise against manual pruning.
  • If you self-host, choose the KV-side architecture first: GQA, MLA, sliding-window or linear hybrids decide whether 1M fits on one node (Qwen2.5-7B-1M needs 120 GB of VRAM).
  • Reach for context parallelism or disaggregated serving only when the job truly is one million-token document; otherwise chunk, retrieve and chain.
