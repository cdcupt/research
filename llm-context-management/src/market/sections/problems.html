The problems practitioners face now — and which are worth solving

The loudest complaints — compaction that forgets mid-task, tool schemas eating the window, sessions that reset — are exactly the ones Anthropic, OpenAI, Google and AWS shipped fixes for in 2025–26. The problems still open, and already budgeted for, are quieter: nobody can measure whether a memory or retrieval layer works, memory stores fill with junk, and compaction silently drops policy.

What breaks, by cluster

Compaction forgets. The most-reported failure in coding-agent trackers. In claude-code #10948 (Nov 2025) auto-compact fires mid-task with "no user control, no warning" and the summary "loses track of file modifications, intermediate decisions, specific technical details"; siblings show it dropping Skills (#13919), project instructions (#24460) and, by June 2026, not firing at all (#66144). Cline compacts below 200K on a 1M model (#9181). The ConstraintRot benchmark (1,323 episodes, 7 model families) finds safety constraints violated 0% in full context, 30% after compaction, up to 59% for some models.

Memory fills with junk and goes stale. A 32-day audit of a production Mem0 store (mem0 #4573) found 97.8% of 10,134 entries unusable: 3,200+ restated the system prompt, 315 were hallucinated profiles, 130 leaked secrets, and one hallucination was re-extracted into 808 entries. A stronger model "extracts more indiscriminately". Stale facts outrank fresh ones because scoring ignores recency (#4956); concurrent writes bypass dedup (#6531); nothing expires.

Nobody can tell whether it is working. Memory is "one of the most common sources of subtle, hard-to-reproduce failures" and RAG metrics "don't fully apply" (mem0 #5235, May 2026). Benchmarks cannot discriminate: on LoCoMo a full-context baseline (~73%) beats Mem0 Graph (~68%) on 16–26k-token conversations (Zep); a filesystem+grep agent scores 74.0% (lhl); Mem0 self-reports 92.5%, benchmark unspecified on Mem0's page and distinct from its 94.4% LongMemEval claim (Mem0). Production RAG shares the blind spot: "the system answers confidently. No error signal is returned" (DigitalOcean); one practitioner guide claims ~40% miss rates and 10–25% reranker gains (unverified; RAG guide).

Tokens, cache and bills are opaque. One 106-tool MCP server injects 54,600 tokens per initialisation (Layered, Jan 2026); Anthropic's example cuts 150,000 tokens to 2,000 with code execution (Anthropic, Nov 2025). Manus runs ~100:1 input:output over ~50 tool calls per task at a 10x cached/uncached price gap (Manus). Server-side state adds opacity: compaction is billed as a separate iteration excluded from top-level usage (docs); Azure customers cannot see what chained state adds per turn (Microsoft Q&A).

Security and governance lag accumulation. MINJA poisons memory with ordinary queries at over 95% success (NeurIPS 2025); memory security "cannot be retrofitted at retrieval or execution time alone" (Lin et al.); a 435-paper survey finds the field over-invests in accumulating state versus "governing, recovering, or relinquishing it" (Always-On Agents). Unlearned data flows back between parameters and memory (Agentic Unlearning); AgentCore events cannot expire under 7 days (Cloud Burn).

What the platforms have already absorbed

Anthropic shipped context editing and the memory tool (Sep 2025), code execution with MCP and tool search (Nov 2025), server-side compaction with a 150,000-token default trigger (Jan 2026) and 1M context at standard pricing (Mar 2026), and calls server-side compaction "the recommended strategy" (docs). OpenAI added Responses-API compaction (Feb 2026) and Agents SDK sandbox memory (Apr 2026). Google's Memory Bank (Jul 2025) "consolidates new memories with existing ones and resolves contradictions"; AgentCore Memory has been GA since Oct 2025; Windsurf and Claude Code bundle session memory.

What vendors have not shipped: compaction fidelity metrics (constraint pinning is a paper, not a product); a neutral benchmark (memory vendors grade themselves); write-path quality gates, audit trails, recency-aware conflict resolution and expiry; and enforceable security or deletion controls, which appear only in blogs (Mem0) and backlogs (semantic-router #1386).

Worth solving versus not

  • Worth a startup's time (rows 1–5). Eval and regression detection for memory and retrieval; silent-failure detection for RAG; write-path hygiene (quality gates, loop breaking, audit); a cross-vendor policy layer that survives compaction; memory security. Each has an existing budget line, a vendor that is the wrong party to grade or police itself, and production rather than benchmark evidence.
  • Features, not companies (rows 6–7). Cross-vendor cost attribution and retention governance are real but narrow; they belong inside an observability or governance product.
  • Not worth it standalone (rows 8–14). Better compaction, MCP slimming, coding-agent session memory, context-rot mitigation and memory consolidation are now native, free, or a model property. Lock-in is widely discussed but nobody is shown paying to fix it.

Implications for a new entrant

  • Sell measurement before mechanism: a memory and retrieval eval harness has no vendor substitute and a known budget holder.
  • Treat compaction and tool bloat as solved inputs; build on Anthropic and OpenAI server-side state rather than against it.
  • Position write-path hygiene as a gating and audit layer in front of Mem0, Memory Bank or AgentCore; metered vendors have no incentive to surface their own junk.
  • Open enterprise conversations with ConstraintRot numbers: 0% to 30% policy violations after compaction is a compliance story.
  • Enter memory security early but expect a 12–24 month sales lag; attack papers are ahead of incidents.
  • Avoid any pitch whose demo is "remember across sessions"; every IDE and SDK vendor ships that.
